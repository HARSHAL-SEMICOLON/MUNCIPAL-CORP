# Phase 1 -- software simulation. Nothing here is hardware-specific.
#
# CPU-only torch. ultralytics depends on torch/torchvision but does not pin a
# build, so a plain `pip install ultralytics` resolves the default PyPI wheel,
# which is the CUDA build -- 500+ MB of NVIDIA libraries a CPU host will never
# use. Free-tier hosts (Streamlit Community Cloud's ~1GB, HF Spaces CPU
# basic) do not have room for that on top of everything else. This index
# line makes pip resolve the small CPU wheels for torch/torchvision instead;
# ultralytics itself still comes from PyPI as normal.
--extra-index-url https://download.pytorch.org/whl/cpu
torch>=2.2
torchvision>=0.17

ultralytics>=8.3          # YOLO detection and tracking

# REQUIRED FOR TRACKING -- do not remove.
# vision/detector.py calls model.track(), and ultralytics' ByteTrack imports
# `lap` (the linear-assignment solver) at tracker-registration time. It is NOT
# a declared ultralytics dependency: locally, ultralytics silently pip-installs
# it on first use, which is why the live loop works on a dev machine. On a
# deployed host that runtime install does not take effect in the running
# process, so model.track() raises ModuleNotFoundError, Detector.detect()
# catches it and returns [], and EVERY upload reports "nothing detected" --
# a dependency failure wearing the costume of an empty frame.
lap>=0.5.12

opencv-python-headless>=4.10   # no GUI/display on a server; smaller, avoids
                                # some libGL edge cases packages.txt covers anyway
numpy>=1.26
PyYAML>=6.0               # config/config.yaml
streamlit>=1.49           # .streamlit/config.toml uses [theme.light]/[theme.dark]
                           # and other keys that only exist from 1.49 on -- an
                           # older resolved version silently drops the whole
                           # theme instead of erroring, so this floor matters.

# --- one deliberate exception -------------------------------------------
# ultralytics declares `ultralytics-platform` as a dependency, and that
# package pins httpx>=0.28. It provides Ultralytics' CLOUD features only --
# it is imported lazily, and only when you touch Platform / AsyncPlatform /
# APIError / APIConnectionError. This project never does: local inference
# uses `from ultralytics import YOLO` and nothing else.
#
# Verified in a clean install (2026-09-14, ultralytics 8.4.150): pip now
# resolves and installs ultralytics-platform + httpx 0.28.1 without
# complaint. The conflict described in earlier notes was specific to an
# environment with an older ultralytics pin alongside a conflicting httpx
# requirement elsewhere (e.g. supabase in the same interpreter) -- it is not
# a problem in a dedicated venv/Space, which this project should run in.
